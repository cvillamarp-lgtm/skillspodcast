Use the `writing-prds` skill to help the user write a Product Requirements Document.

Start by asking:
1. What problem is this solving, and why does it matter now?
2. Who is the customer?
3. How will you measure success?

Then guide them through writing a complete, lightweight PRD using the frameworks from Maggie Crowley, Bill Carr, and Aparna Chennapragada. Flag common mistakes like starting with the solution or missing success criteria.
